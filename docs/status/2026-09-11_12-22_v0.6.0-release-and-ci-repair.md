## Executive Summary

The question "v0.5.1?" turned out to be three problems in one:

1. **Version math was wrong.** Since v0.5.0, a brand-new public package (`pkg/provider`, the BuildFlow/toolsdk integration) had landed under heuristic auto-commit messages that said nothing. That is a MINOR bump (new public API + new `toolsdk` dependency), so the release became **v0.6.0**, confirmed with the user before the irreversible tag push.
2. **CI was silently dead.** The CI workflow was in state `disabled_manually` (left over from the Jul–Sep 2026 Actions billing block). Release stayed active, so releases shipped while pushes skipped validation entirely. The current master code (including `pkg/provider`) had **never** been CI-validated.
3. **CI was broken anyway.** Even enabled, the `test` job failed on any push (`pnpm` no longer exists on ubuntu-latest runners) and the `nix` job failed on any push (`nix flake check --systems` is not a valid flag). Both fixed this session.

**Net result:** v0.6.0 is tagged, published, signed, SBOM'd, on ghcr.io, and indexed by the Go module proxy at the exact CI-green commit. The CI pipeline is re-enabled, green, and manually dispatchable.
